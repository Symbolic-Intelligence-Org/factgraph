## 1. Current Stage

This session identified the root cause of bounded-seed non-propagation and fixed the adapter:

- **Root cause**: PyReason's rule body clauses default to threshold `[1,1]`. A seed with bound `[0.85, 0.95]` fails the `is_satisfied()` check against `[1,1]`, so the rule never matches.
- **Fix**: `PyReasonRuleExt.body_predicate_bounds` allows explicit per-predicate thresholds. Both compilers (`rule_ext.py` + `where_compile.py`) emit `: [lo, hi]` syntax on body clauses.
- **Real-engine verified**: bounded seed + explicit threshold → rule matches ✓
- **Important caveat**: derived head bound is still `[1,1]`, NOT the input interval. PyReason does not transport fuzzy intervals as payload — it propagates boolean truth with threshold-gated matching.

## 4. New Capability: `body_predicate_bounds`

```python
# Before: bounded seed silently ignored
PyReasonRuleExt(timestep_delay=1)

# After: bounded seed participates in matching
PyReasonRuleExt(
    timestep_delay=1,
    body_predicate_bounds={"user:popular": (0.5, 1.0)},
)
```

Compiles to: `popular(x) <-1 popular(y) : [0.5, 1.0], Friends(x,y)`
