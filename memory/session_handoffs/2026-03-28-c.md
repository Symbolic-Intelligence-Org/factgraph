## 2. Key Finding: PyReason Rule Engine Non-Functional

### Evidence

```python
# Simplest possible test — should derive b(X)=[0.8,0.9] from a(X)=[0.8,0.9]
g = nx.DiGraph()
g.add_node('X', a=1, b=0)
pr.load_graph(g)
pr.add_rule(pr.Rule('b(x) <-0 a(x)', 'simple'))
pr.add_fact(pr.Fact('a(X) : [0.8, 0.9]', 'init', 0, 2))
interp = pr.reason(timesteps=2)
# Result: Fixed Point iterations: 1, b(X) never appears
```

### Diagnosis

- `pr.add_rule()` correctly parses and stores rules (verified via `pr.get_rules()`)
- `pr.load_graph()` correctly loads graph with attributes
- `pr.reason()` runs without error but `Fixed Point iterations: 1` means rules never fire
- The numba JIT-compiled `reason()` function in `interpretation.py:405` is the suspect
- Likely a numba 0.64.0 type inference issue on Apple Silicon (similar to the Python 3.13 `Cannot unify int64 and Tuple` error seen earlier, but silent on Python 3.10)

### Recommended Next Steps

1. **Try on a different platform** (Linux x86_64 with same pyreason/numba versions)

3. **Try pyreason 2.x** which may use a different numba compilation strategy
4. **Try NUMBA_DISABLE_PERFORMANCE_WARNINGS=1 NUMBA_BOUNDSCHECK=1** to expose silent failures
