## 6. Frozen Contracts

Core lifecycle/assets contracts:

- `FactGraph.create(schema_classes=[...])` is the canonical first-contact SDK
  constructor.
- `FactGraph.create(path=...)`, `fg.save(...)`, and
  `FactGraph.load(path, schema_classes=[...])` own workspace lifecycle.
- `from_schema_classes(...)` remains lower-level and does not accept `path=`.
- `SavedRuleRef` and `SavedInferenceRef` are load handles, not runtime
  selectors.
- `RuleRef` remains a where-clause carrier, not a saved-asset handle.
- Public service / registry vocabulary is `inference`; candidate/internal
  substrate may still use `derivation_id`.

Schema mutation contracts:

- Schema mutation is additive-only.
- Entity-add may add new entity classes only.
- Field-add may replace same-name entity classes only to add non-identity
  fields.
- Identity changes, field removal, type/cardinality changes, relationship
  target rewrites, and predicate-id collisions reject before mutation.
- Superseded classes/descriptors reject at SDK boundaries.
- No default/backfill semantics exist for field-add.
- Ledger and registry schema digests update immediately; workspace manifest
  updates on explicit `fg.save(...)`.

Confidence cleanup contracts:

- Legacy generic confidence is parse-compatible but not emitted by default.
- Generic confidence does not become assertion meta, shared semantic
  annotation, adapter semantic input, or evidence/certainty display by default.
- Adapter-native ProbLog/PyReason semantic lanes remain the only adapter export
  source for uncertainty semantics.
