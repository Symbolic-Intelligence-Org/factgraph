## 2. Engineering Conclusions (frozen in repo)

These are verified by experiment and encoded in code/docs:

1. **Edge labels must be graph attributes** — PyReason requires `graph.edges[u,v][label] = value`. Edge labels via `pr.add_fact()` do not participate in rule matching.
2. **Node labels must go through `pr.add_fact()`** — Node labels as graph attributes do not trigger rule propagation.
3. **Only `[1,1]` bound seeds participate in propagation** — `pr.Fact('label(node) : [0.85, 0.95]')` is accepted by PyReason but does NOT serve as a propagation source. Runner now emits `UserWarning` when this pattern is detected.

## 3. Observed Behavior (NOT frozen as contracts)

These are experimental observations, not framework guarantees:

4. **Same-label propagation works** — `popular(x) <-1 popular(y), Friends(x,y)` successfully propagates `popular` from source to target. Head label must match at least one body label.
5. **Cross-label derivation not verified** — `compliant(x) <-0 disposal(x), passivation(x)` never produced output in any test. Not frozen as a compiler constraint because upstream PyReason source doesn't explicitly forbid it.
6. **`pr.reset()` has global state residue** — Multiple `reset()` calls in the same process can produce different results from the first call. Each test should ideally run in a fresh process.
