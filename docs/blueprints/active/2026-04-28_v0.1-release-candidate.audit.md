## Decision Notes

1. **RC verification is not publish workflow**
   - **Decision**:This blueprint only verifies whether a v0.1 release candidate is plausible. It does not publish to PyPI, tag a release, create a GitHub release, or reserve `factpy-kernel`.
   - **Why**:OS-prep readiness closed the release shape, but user explicitly flagged that code readiness still needs a separate judgment.
   - **Impact**:Wheel build/install verification can run as a confidence check, but any upload/trusted publishing action requires a separate release-day workflow.

2. **Hard gates focus on installed kernel behavior**
   - **Decision**:The first RC hard gates are wheel content, metadata, clean install, README quickstart, audit optional-domain behavior, tests, and kernel Ruff.
   - **Why**:These are the user-visible risks for a kernel-only PyPI package.
   - **Impact**:mypy and service/tools Ruff stay in the soft-risk register unless they affect installed kernel behavior.

3. **Verdict thresholds are explicit**
   - **Decision**:
     - `pass` requires all hard gates green without changes.
     - `conditional pass` allows at most two trivial local fixes,each no more than 30 minutes,with rerun evidence.
     - `block` is required for any substantive fix or repeated hard-gate failure.
   - **Why**:The RC pass produces a go/no-go verdict,so the standard must be reproducible rather than purely judgment-based.
   - **Impact**:Implementation can proceed without ambiguity;hard-gate failures either become small audited commits or a blocker verdict.

4. **RC pass on commit `f38985c` (post-fix `e9dd311`); verdict = `conditional pass`**
   - **Decision**:RC verification ran in foreground per blueprint §8;result is `conditional pass` because Hard gate 1.2 required a one-file inline fix (no semantic change,packaging metadata only).
   - **Hard gates (post-fix wheel)**:
     - 1.1 wheel includes `kernel/`:✓ (156 non-test entries)
     - 1.2 wheel excludes `kernel/tests/`,`agent/`,`service/`,`domains/`:✓ post-fix (49 → 0 `kernel/tests/*`;0 each for the other three)
     - 1.3 / 5 metadata excludes private extras / AGPL parser deps:✓ (only `[dev]` extra;no PyMuPDF / PyMuPDF4LLM)
     - 2 clean install smoke:✓ (kernel,kernel.sdk,kernel.application,kernel.audit all import;34 SDK public symbols)
     - 3 README quickstart smoke:✓ (`Alice` output,exit 0,no monorepo paths)
     - 4 audit optional-domain smoke:✓ (`AuditOptionalDomainError` raised,`__cause__ = ModuleNotFoundError`,no raw `ImportError` leak)
     - 6 test and lint baseline:✓ (kernel ruff 0 errors;5-segment regression 1097 OK / 3 skips)
   - **Soft gates / risk register**:all recorded per blueprint §5.2;no reclassification.
   - **Why `conditional pass` not `pass`**:this run required an inline fix (`e9dd311`). A clean future RC pass against the post-fix repository state would record `pass` without further changes.
   - **Why not `block`**:the fix was packaging-only,under 30 minutes,fully resolved by adding a single empty `__init__.py`. Hard gate 1.2 re-ran green on the rebuilt wheel,and no other gate uncovered substantive issues.
   - **Next action authority**:user decides release-day workflow timing;this RC produced no publish artifact,no tag,no PyPI reservation. Wheel under `dist/` is a verification artifact only and should not be uploaded.
   - **Impact**:RC blueprint `Status: scoped → implemented`. The four `implemented` blueprints (OS-prep readiness,runtime-authority cleanup,audit-delivery contract,this RC) are candidates for archive after actual v0.1 publish + short stability window.
