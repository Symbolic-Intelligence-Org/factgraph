## Decision Notes

### 关键决策(2026-04-27 draft)

1. **从 namespace-split blueprint 继承未决问题作为 scope 起点**
   - **Why**:archived blueprint §10 OS-prep TODOs(PyReason license / 包名 / LICENSE / CI gate / OpenAPI yaml 归属 / list_compliance_matrix 架构净化)是已识别但当时不在 scope 的工作;namespace 层面已稳定后,这些是自然的下一阶段
   - **影响**:本 blueprint 的 §2 Goals 和 §5.1 决策矩阵直接对应这些未决项

2. **Draft 阶段不预先决定 OS scope / 包名 / LICENSE 等具体决议**
   - **Why**:这些是高 leverage 决策,值得在 scoped 阶段专门讨论(可能涉及商业策略 / 受众定位 / 与 audit 报告 2026-04-20 的市场结论对齐),不在 draft 阶段单方面预设
   - **影响**:§5 Proposed Shape 只列待决策矩阵 + 决策依赖图 + 推荐起步顺序;具体方案在 scoped 时填入

3. **明确 non-goals 防止 scope creep**
   - **Why**:OS prep 容易被"顺便重构 god file" / "顺便加 feature" / "顺便改 namespace 内部" 等不相关工作扩大
   - **影响**:§3 显式列 5 类 non-goal;商业化 / 销售 / 客户叙事归 audit 报告线,不进 OS-prep

4. **工程 trap 提前纳入 §6 Boundaries**
   - **Why**:5 工程 trap(zsh for-in / BSD sed `\b` / pre-flight 实跑 / __init__ re-exports / 跨包相对 import)在 namespace-split blueprint 实施期才发现并补救,本 blueprint 应预先纳入 implementation checklist
   - **影响**:§6 已列工程 trap section;OS-prep 实施时不必再重新踩
