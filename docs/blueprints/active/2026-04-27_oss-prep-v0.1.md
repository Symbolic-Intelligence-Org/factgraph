## 1. Problem

Namespace split(2026-04-27 commit `0f2ee52`)已扫清 kernel 的架构债,但 OS 公开发布还有一批**决策性 + 工程性**前置工作未做。这些工作**单看每一项都不复杂**,但**互相牵制**(包名决定影响 PyPI publishing;LICENSE 决定影响 PyReason 是否能进 OS extras;OS scope 决定影响 OpenAPI yaml 归属),适合在一个 blueprint 里一次性收口。

本 blueprint 的目标是:从"namespace 干净的 monorepo"走到"可以面向公众的 v0.1 OSS release"。

## 2. Goals

(每条对应 archived blueprint §10 + memory/current.md 已识别的 OS-prep TODO;顺序与 §5.1 决策矩阵一致)

- **Artifact topology**(✅ scoped):v0.1 选 single distribution / multi namespaces;multi-distribution 降级为未来演进路径
- **Publication scope / PyPI policy**:公开 repo + 立即上 PyPI / 公开 repo + 暂不上 PyPI / 公开 repo + PyPI 发布有节奏
- **OS visibility scope**(✅ scoped):全 4 namespaces public,kernel/service primary,agent/domains experimental(支持级别分层)
- **包名最终决定**:沿用 `factpy-kernel` / 换名(需 PyPI 可用性查证)
- **LICENSE 合规**:新建 LICENSE 文件 + 依赖 license 审计 + LICENSE 兼容性确认
- **PyReason license 查证**(✅ scoped):BSD-2-Clause(verified,permissive),可进 default extras;PyPI metadata 的 "BSD 3-clause" 是作者错标,法律真相以 LICENSE.md 为准
- **OpenAPI yaml 归属决策**:kernel-only / agent-only 双 yaml / composed / 弃用文件契约 / 暂不发布
- **CI quality gates 增强**:在已修复的 baseline(commit `30a29b0`)之上加 ruff / mypy / coverage(audit 报告 2026-04-20 点名缺失)。注:**baseline CI 修复已完成**,不在本 blueprint scope 内
- **仓库根清理(逐项分类)**(✅ scoped):1 bridge(`factpy-kernel-report-audit-2026-04-20.md` → `docs/references/bridges/`,已完成)+ 9 keep-local(`archive/` / `out/` / `esa_demo_output/` / `dora_demo_output/` / `test.ipynb` / `context.md` / `关于mvp的思考.md` / `best_conf.csv` / `path_conf.csv`,均已 untracked)+ 0 delete;实证 `git ls-files | grep ...` 空输出 ✓
- **新增 CONTRIBUTING / CODE_OF_CONDUCT**:OS 标配
- **README 是否再调整**:目前 README.md / README.en.md 是 namespace-split 时重写的"内部+外部混用"形态,OS 时可能需要更面向外部读者
- **(可选)架构净化**:`kernel/audit/query.py.list_compliance_matrix` 的 lazy import 是 namespace split 的过渡方案;OS-prep 是合适窗口决定是否进一步迁出 kernel(整理 kernel→domains 边界)

## 3. Non-goals

- **不**做 god file refactor(`sdk/batch.py 1838` / `sdk/store.py 1499` / `service/runtime_v1.py 2810`)—— 内部代码质量,post-OS 单独 blueprint
- **不**加新功能(extraction precision、agent capabilities 等)
- **不**做 namespace 内部子结构重组(本轮 namespace split 已经稳定 4 个 packages,不再动)
- **不**讨论商业化 / 销售策略 / 客户叙事(那是另一条线,见 audit 报告 2026-04-20)
- **不**做 v1.0 stable API 承诺 —— OSS v0.1 是 "试水",API surface 不冻结
