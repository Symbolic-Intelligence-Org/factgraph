## 1. Problem

v0.1.1 proved a safe replay loop: patch a derivation atom, recompile, re-evaluate, then compare candidates and shallow evidence metadata. v0.1.2 added the missing authoring-layer module substrate: derivation body atoms can now be represented as stable owner/path-scoped modules, lowered back to tuple-form runtime `where` IR, and mapped from support artifact keys back to module ids.

The next natural operation is disabling one condition module for a replay run. This is different from deleting evidence and different from mutating a compiled plan. It should create a temporary rule/derivation variant, run the normal compile / validate / evaluate path, and return the same replay/diff/evidence surfaces already established in v0.1.1/v0.1.2.

The open design question is the semantics of "disable". In a branch body where atoms are AND-connected, disabling an atom could mean physically dropping the atom before compile, replacing it with a no-op truth atom, adding a disabled metadata flag that lowering interprets, or applying an overlay outside the authoring payload. Each choice has different effects on variable binding, `body_confidences`, support key mapping, branch arity, evidence comparability, and user expectations.

Step 0 completed the source-backed feasibility spike and selected a native
runtime overlay. The blueprint is now scoped for implementation.

## 2. Goals

- Define source-backed semantics for disabling one condition module in a replay variant.
- Preserve the v0.1.1/v0.1.2 boundary: rule/derivation variants are operable; evidence remains read-only and run-derived.
- Preserve and extend the public `SDKStore.replay_with_patch(...)` compatibility surface.
- Decide whether the first public API is a new method, a patch action, or a module-aware helper.
- Ensure disabled-condition replay still goes through compile / validate / evaluate before candidate results are trusted.
- Keep RuleRef-bound replay, candidate universes, audit JSONL persistence, and parameter handles out of scope unless Step 0 explicitly re-scopes them.

## 3. Non-goals

- No mutable evidence tree API.
- No compiled-plan in-place rewrite.
- No proof-frame local re-evaluation as source of truth.
- No persistent rule variant storage or promotion to a new rule version.
- No `param_override`, threshold slider, or Parameter Handle implementation.
- No add-condition operation.
- No lazy why-not / red-green completeness board.
- No cross-engine disable semantics unless separately proven.
- No RuleRef-bound replay support unless Step 0 changes scope.
- No audit JSONL persistence of replay events in this blueprint.

## 5. Proposed Shape

v0.1.3 implements disable-condition as a replay-time native runtime overlay.
It does not delete the atom from the authoring payload, does not remove it
from module IR, and does not rewrite a compiled plan.

```text
authoring derivation/rule body
  -> module IR over the complete body
  -> lower complete body to tuple-form where IR
  -> evaluate original normally
  -> evaluate variant with disabled_locators overlay
       - where evaluator skips disabled atoms
       - support capture skips disabled atoms
       - Python enumerate preserves original atom indices
  -> candidate diff + shallow evidence/module mapping
```

The public SDK entry point remains `SDKStore.replay_with_patch(...)`, extended
with an explicit action sentinel:

```python
def replay_with_patch(
    self,
    derivation,
    *,
    locator: str,
    new_atom: Any | None = None,
    action: Literal["replace", "disable"] = "replace",
) -> ReplayResult:
    ...
```

Action contract:

| action | new_atom | Behavior |
| --- | --- | --- |
| `"replace"` | not `None` | Existing v0.1.1 atom replacement behavior |
| `"replace"` | `None` | Fail with `SDKStoreError(code="REPLAY_INVALID_PAYLOAD")` |
| `"disable"` | `None` | New v0.1.3 disabled-condition replay behavior |
| `"disable"` | not `None` | Fail with `SDKStoreError(code="REPLAY_INVALID_PAYLOAD")` |

`ReplayResult` gains one additive field:

```python
disabled_locators: tuple[str, ...] = ()
```

The variant payload still contains the full `where` / `body`. The variant
module map is still computed from the full body. Disabled locators are a
runtime replay overlay, not a persistent rule shape.

### Source-Backed Step 0 Decisions

1. **Do not drop atoms.** Dropping would shift downstream atom positions
   and break the `b{branch}.a{atom}` support-key/module-map relationship.
2. **Do not use a no-op atom.** There is no existing native no-op/truth atom
   in `where_eval.py`; adding one would expand the where language and leak
   into validators/backends.
3. **Use native-only overlay.** `where_eval.evaluate_where(...)` owns the
   atom dispatch loop. `_support_capture.py` owns support artifact emission
   loops. Both already enumerate branch atoms; adding a `continue` for a
   disabled locator preserves Python's original enumerate index.
4. **Keep v0.1.1/v0.1.2 replacement behavior unchanged.** `action="replace"`
   keeps the existing `replace_atom(...)` path and module-aware lowering.
5. **Keep RuleRef-bound replay rejected.** The current dict replay path still
   loses registry context; `REPLAY_UNSUPPORTED_DEPENDENCIES` remains the
   boundary.

## 6. Boundaries And Invariants

- Compile / validate / evaluate remains authoritative.
- Evidence remains read-only and run-derived.
- Disable-condition must produce a temporary replay variant, not mutate the source rule/derivation in place.
- Existing `replay_with_patch(...)` behavior must remain compatible.
- Existing locator support (`b{branch}.a{atom}`) must remain valid.
- Module ids must remain stable and owner/path-scoped.
- Any disabled atom semantics must account for variable binding before evaluation.
- Any disabled atom semantics must account for support-key/module mapping after evaluation.
- RuleRef-bound replay remains rejected unless Step 0 explicitly proves a safe registry-context carrier.
- `original_payload.where` and `variant_payload.where` remain complete; disable
  does not remove atoms from payloads.
- `original_module_map` and `variant_module_map` are both computed from the
  complete body and include disabled locators.
- `condition_weights` / `b{branch}.a{atom}` locator keys are not shifted.
- A disabled atom must not generate a support key, but adjacent atom support
  keys keep their original locator numbers.
- Variable binding failures surface through the existing compile / evaluate /
  where-validation errors. v0.1.3 does not introduce new error infrastructure
  for unbound variables caused by skipped atoms.
- The disabled overlay is native replay-only. Souffle / ProbLog / PyReason
  disable semantics remain out of scope.

## 8. Implementation Plan

### Step 1 — Native Disabled Locator Substrate

Add disabled-locator threading through the native runtime only:

- `where_eval.evaluate_where(..., disabled_locators=())`
- native/ruleref substrate pass-through for non-RuleRef replay paths
- `_support_capture.build_support_artifact_for_binding(..., disabled_locators=())`
- `_support_capture.find_winning_branch_index(..., disabled_locators=())`
- `_support_capture.derive_rule_ref_edges_for_binding(..., disabled_locators=())`
- `_evaluate_where_over_view_with_support(..., disabled_locators=())`

Implementation rule: branch loops must use `enumerate(branch)` and `continue`
when `f"b{branch_index}.a{atom_index}"` is disabled. Do not pre-filter the
branch list.

Step 1 does not expose a public SDK API.

### Step 2 — SDK Replay Action

Extend `SDKStore.replay_with_patch(...)` and
`sdk_replay_with_patch(...)` with:

```python
action: Literal["replace", "disable"] = "replace"
new_atom: Any | None = None
```

`replace` uses the existing `replace_atom(...)` path. `disable` leaves the
variant payload unchanged, module-lowers the full body, and evaluates the
variant through the native disabled-locator overlay. Engine / RuleRef rejection
boundaries remain unchanged.

Prefer an internal replay-only evaluation path over adding a general public
`SDKStore.evaluate(..., disabled_locators=...)` keyword. The overlay is not a
general evaluation feature in v0.1.3.

### Step 3 — ReplayResult And Evidence Mapping

Add:

```python
disabled_locators: tuple[str, ...] = ()
```

to `ReplayResult`.

Verify support/module mapping invariants:

- disabled locator remains present in `variant_module_map`;
- disabled locator is absent from support artifact keys;
- later support keys keep original locator indices.

### Step 4 — Docs And Close-Out

Update SDK docs with:

- action contract and invalid argument combinations;
- native-only replay boundary;
- disabled support-key behavior;
- warning that disable is an evaluation overlay, not persistent rule mutation.

Close the blueprint with final test baseline, deviations, and archive plan.

### Deviations From Scoped Blueprint

No behavioral deviations from the scoped native-overlay design.

The main implementation detail was deliberately conservative: `disabled_locators`
was not exposed as a public `SDKStore.evaluate(...)` keyword. It remains an
internal replay-only path behind `replay_with_patch(action="disable")`.

### Why Deviations Were Accepted

The public-surface decision is consistent with the scoped blueprint's
recommendation to prefer an internal replay-only evaluation path. It avoids
turning replay overlays into a general SDK evaluation contract before
multi-operation overlays and parameter override semantics are designed.

### Archive Plan

Keep this blueprint in `docs/blueprints/active/` while the stacked
v0.1.1/v0.1.2/v0.1.3 line remains under merge/release review. Archive after the
stack is merged or intentionally abandoned, together with the related rule-replay
reference bundle.
