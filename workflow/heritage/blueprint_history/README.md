# Legacy Blueprint History

`docs/blueprint_history/` 保存项目历史阶段遗留下来的蓝图文档。

这些文档的价值主要在于：

- 记录当时的设计意图
- 保留被采纳、被放弃或未完成方案的上下文
- 为当前任务蓝图提供历史 rationale

这些文档不承诺：

- 与当前代码行为完全一致
- 覆盖所有后续实现变化
- 充当当前模块实现的权威说明

## 使用规则

- 当前实现真相请优先看 `src/factpy_kernel/*/docs/`
- 新任务请在 `docs/blueprints/active/` 中创建 blueprint，不要直接写到本目录
- 若引用本目录文档，应该明确它是历史依据而不是当前契约
- 若某篇历史蓝图需要进入新归档体系，应在 `docs/blueprints/archive/` 中创建显式标注的 reconstructed archive 条目，并保留对本目录原始文件的链接

## 状态标注约定

历史蓝图建议在文档开头显式标注状态。当前仓库里已经存在零散标注，但尚未完全统一。

推荐使用以下几类：

- `状态：已实现`
- `状态：部分实现`
- `状态：讨论中 · 尚未实现`
- `状态：历史讨论`

可选补充字段：

- `类型：协议蓝图 / 架构蓝图 / 性能蓝图 / 概念草案`
- `说明：` 一句明确“是否为当前实现真相”

说明：

- 这是一条逐步收口的约定，不要求一次性重写所有旧文档。
- 新迁入本目录的历史文档应优先补齐这种状态头。

## 说明

- 本目录中的部分内部链接仍指向旧路径，这是历史遗留现象。
- 若某篇文档仍有现实价值，优先在新 blueprint、模块 docs 或原则文档中重新表述，而不是把旧文直接改写成现状。
