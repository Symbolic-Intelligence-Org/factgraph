## 8. Known Gaps / Next Steps

### 8.1 CRITICAL: PyReasonSession needs entity-level batch API (IMMEDIATE NEXT TASK)

**This was the last discussion topic before handoff.**

**Current state**: `PyReasonSession` exposes `write_node_fact(pred_id, ...)` and `write_edge_fact(pred_id, ...)`. Users must manually know which predicates are node vs edge, and work at the pred_id level.

**Problem**: SDK's Souffle path writes at entity level: `tx.entity(User, ...).name.set("Alice")`. System auto-decomposes into minimal facts. PyReason session should follow the same pattern.

**Target design** (discussed, not implemented):

```python
with pyreason_session.batch() as tx:
    alice = tx.entity(User, user_id="Alice", locale="en")
    alice.name.set("Alice", bound=[1.0, 1.0])
    alice.popular.set("true", bound=[1.0, 1.0])

    bob = tx.entity(User, user_id="Bob", locale="en")
    bob.name.set("Bob", bound=[1.0, 1.0])

    tx.relationship(Friends, from_entity=alice, to_entity=bob,
                    strength="0.9", bound=[0.9, 0.9])
    tx.commit()
```

System auto-routes to `_write_node_fact_internal` / `_write_edge_fact_internal` based on schema. User never sees node/edge distinction.

**Implementation approach**:
1. Add `batch()` context manager to `PyReasonSession`
2. Add entity proxy (`tx.entity(User, ...)`) that returns a field-setter
3. Field setter's `.set()` / `.add()` accepts `bound` param (engine-specific)
4. Add `tx.relationship(Friends, ...)` for edge facts
5. `write_node_fact` / `write_edge_fact` become internal methods
6. Existing tests need migration to new API
7. Integration demo needs update

**Files to change**: `adapters/pyreason/session.py`, `tests/test_pyreason_session.py`, `examples/pyreason_integration_demo.py`
