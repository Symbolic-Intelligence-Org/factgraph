**C. PyReason Accept Bridge** (`731e8b0`)

- Synthetic entity_ref materialization: `Alice → idref_v1:User:Alice`

**Current position**: PyReason annotation pipeline is **fully closed-loop**: session → batch API → annotation templates → accept → Ledger persistence → `find_annotations()` queryable. The natural next step is **PyReason evaluate-and-accept path v0** (run config → session population → engine execution → accept → result/provenance export).

## 7. Frozen Contracts

**Prior frozen contracts 1-27 remain frozen.** This session adds:

28. **Annotation is an independent layer** — not an extension of `meta_rows`. Separate `annotation_rows` table with `namespace/category/key/kind/value/origin/derivation`. (Decision blueprint §D1)
29. **`confidence` is a derived summary** — not a unified truth semantics. `origin="derived"`, `derivation="pyreason:lower_bound"`. (Decision blueprint §D2)
30. **Engine truth interpretation = semantic annotation, not claim** — `bound`, `probability`, `boolean truth` belong to `annotation(pyreason/semantic/*)`, not to `claim(pred_id+args)`. (Decision blueprint §D3)
31. **Initial annotation scope: assertion only** — no candidate/provenance_entry annotation yet. (Decision blueprint §D4)
32. **`meta_rows` = legacy compatibility layer** — new truth semantics only enter Annotation Store. (Decision blueprint §D4 corollary)
33. **Rule engine-specific semantics: typed rule extensions, not annotation** — `engine_ext=PyReasonRuleExt(...)` on Rule/Derivation. `Query` does not split. (Decision blueprint §D5)
34. **Rule definition-time vs run-time separation** — `timestep_delay` → rule extension; `timesteps=5` → `engine_options`. (Decision blueprint §D6)
35. **Annotation Store kind system** — reuses MetaRow kinds: `str/int/float/bool/time/json`. No interval kind. (Decision blueprint supplementary)
36. **`(fact_kind, fact_index)` binding key** — template-to-assertion binding uses this pair, not a more complex ID. (Accept blueprint)
37. **`shared/*` annotations written by `set_field()` only** — accept helpers never duplicate them. (Accept blueprint)

**Superseded contract**: Contract #24 ("Confidence stays float in shared layer; PyReason bound → confidence mapping in engine session") is superseded by contracts #28-29. The mapping is now explicit: `confidence` is a derived summary with `derivation="pyreason:lower_bound"`, and engine-native values are preserved in `pyreason/semantic/*` annotations.

**Revised contract**: Contract #25 ("Engine-specific Rule subclasses — PyReasonRule, ProbLogRule") is refined by contract #33: prefer `engine_ext` payload composition over full subclass hierarchy.

## 8. Known Gaps / Risk Assessment

### 8.1 PyReason Evaluate-and-Accept Path v0 (RECOMMENDED NEXT)

**What exists**:
- `PyReasonSession` with batch API and annotation templates
- `accept_pyreason_session()` that persists to Ledger
- PyReason provenance carrier (`PyReasonTraceV0`)
- Integration demo that runs PyReason engine with manual graph building

**What's missing**:
- Formal evaluate dispatch (`mode="pyreason"`)
- Run config (`engine_options={timesteps: N}`)
- Session population from schema + data source
- Result normalization to standard candidate format
- Provenance export to audit pipeline

**Key scoping questions**:
- Does the first evaluate path need to support rule compilation, or can it work with hand-written PyReason rules?
- Should the evaluate path produce `CandidateSet` or a PyReason-specific result type?
- How does `engine_options` get passed through? Via `Store.evaluate()` or a separate dispatcher?

### 8.2 Entity Identity / entity_ref Alignment

**What exists**: Accept helper uses synthetic `idref_v1:{EntityType}:{raw_id}` materialization.

**What's missing**: Proper entity registry integration. Currently, PyReason graph IDs (bare strings like "Alice") are converted to synthetic entity_refs at accept time. This works but doesn't integrate with the SDK's entity reference system.

### 8.3 Rule Builder (`engine_ext`)

**What exists**: Decision blueprint freezes `engine_ext=PyReasonRuleExt(...)` pattern.

**What's missing**: No implementation. `PyReasonRuleExt` doesn't exist. Layer 2 typed rule extensions are design-only.

### 8.4 Downstream Consumer Migration

**What exists**: Annotation Store is populated. `find_annotations()` works.

**What's missing**: No consumer reads `pyreason/semantic/*` annotations. Audit UI, static HTML, and service queries all still read from `meta_rows`.

### 8.5 Known Debt (carried forward)

- ProbLog `body_confidences` in core evaluate (ADR-14c.1)
- Mother blueprint `implemented` but not formally archived
