## 1. Problem

Q-NAMING decision §4.4 locks deletion of 20 legacy SDK flat shell methods on `SDKStore` (and the `FactGraph = SDKStore` alias) — i.e., the `fg.<method>(...)` top-level call surface that predates the namespaced-manager redesign. Audit §4 (Batch C) at `10de33b9` measured the blast radius: 132 hits / 33 files (4 src, 2 test, 27 docs/workflow) — Yellow risk, low external callsite blast.

**Hidden dependency** flagged by audit §4 + sharpened by Step 4.2 review (Codex P2-1 / P2-2 / P2-3): the shipped delegation graph from namespaced managers into delete-list flat shells is **more nuanced** than the audit summary suggested:

- **Reachable, live, public namespaced managers** that currently call `self._sdk.<flat>(...)` and MUST be rewired before delete: `_SDKEvalManager` (3 methods), `_SDKSchemaManager` (2 methods — P2-1 finding), `_SDKRulesManager` (1 method — P2-1 finding), `_SDKAuditManager.diff_proof_frames` (1 method — `explain` + `conflicts` already rewired by Q-NAMING-AD per AD PF-R1 Option (a)). Total: 7 method rewires across 4 reachable managers.
- **Non-public / dead-code manager classes** (P2-2 finding): `_SDKWhatIfManager`, `_SDKWhatIfFactOverlayManager`, `_SDKWhatIfRuleManager` exist in source but have NO public access path — `SDKStore` has no `what_if` property and no `_what_if_manager` initialization. `tests/sdk/test_t5_legacy_hard_cut.py` asserts `hasattr(graph, "what_if")` is false. These manager classes are dead leftovers, NOT live rewire targets.
- **Tombstone flat shells** (P2-3 finding, refined by Step 4.3 PF-v1): **11 of the 20 flat shells** are not implementations but tombstone stubs raising `SDKStoreError(_T5_LEGACY_SHELL_REMOVED.format(...))`. These have no body to rewire; only the public stub is deleted. (Step 4.1 scan estimated 9; PF-v1 added `accept` + `accept_many` after fresh re-read.)

Sub-Q3 (locked at Q-NAMING adopt) requires **single-slice combined refactor + delete**: move flat-shell bodies into namespaced manager method bodies or private helpers, then delete public flat shells, all within one blueprint. This matches the Slice 3a Step 7 precedent and the Q-NAMING-AD §5.4.1 Option (a) precedent (private helper in `_SDKAuditManager` reaching core through `self._sdk._store.<method>(...)`).

Q-NAMING-AD already partially completed this work for `_SDKAuditManager.explain` and `_SDKAuditManager.conflicts` (rewired to call `self._sdk._store.explain_fact/.conflicts` directly per AD PF-R1 Option (a)). Q-NAMING-C completes the same pattern across the remaining live reachable managers + classifies each flat shell as live / tombstone / passthrough / documented (G6 per-shell classification) + decides the `commit_assertions` fate per Q-NAMING §4.4.2 explicit TBD + decides the dead `what_if` manager class fate (delete or leave as non-public leftover, but NEVER resurrect `fg.what_if` public access).
