### 2026-05-30 — `fg.entities.delete` guard-bypass 设计 — **P1 amend 2026-05-30 推翻 metadata marker 改为 path-binding**

**原 lock(draft `fb9ec2e2`)**:`plan_delete_command` 内部 build retract PlannedOpDTOs 时设 `meta["__delete_via_entities_delete__"] = True` marker;`_apply_op` retract branch 见 marker 时跳过 `check_retract_allowed`。

**Reviewer P1 反馈(2026-05-30)**:`meta` 是 DTO metadata surface,不能作为 protected Identity Claim retract 的权限信号;否则未来任何能构造 `PlannedOpDTO` 的 application-level caller 都可能伪造 bypass(`PlannedOpDTO(op="retract", meta={"__delete_via_entities_delete__": True}, ...)` 绕过 INV-7c)。该设计违反 trust boundary 原则。

**修复 lock(amend after P1)— path-binding 替代 metadata signal**:
- NEW private helper `_apply_entity_delete_retract(op, *, store, index)` 是 application-internal **only**
- **只由** `apply_delete_plan` 直接调用
- **不**出现在 `_apply_op` retract branch 任何 code path 内
- generic `_apply_op` retract branch **永远** 调 `check_retract_allowed`,任何 application-level caller 不可绕过
- ADR-IC §4.1 强制点 3 "整批撤销只能作为 `fg.entities.delete` 的一部分" 通过 **path-binding 结构性保证**:能调到 `_apply_entity_delete_retract` 的唯一函数是 `apply_delete_plan`,而 `apply_delete_plan` 只能由 SDK `fg.entities.delete` → `plan_delete_command` → `apply_delete_plan` 链路触发
- **PlannedOpDTO shape 不动**(`meta` 不引入 bypass field)— Q-PR1 carve-out + DTO contract 友好
- **Structural test invariant**(Step 3.6 + §7.2 acceptance):`_apply_op(PlannedOpDTO(op="retract", assertion_id=identity_asrt_id, ...))` 直接调 generic dispatcher 仍 raise `EntityWriteError(INV_7C_IDENTITY_PROTECTED)` — 证明 generic path 不 bypass guard。`_apply_entity_delete_retract` 不在 `_apply_op` 内 verified by grep + import check(防 future drift)

**为什么 path-binding 比 metadata signal 安全**:
- metadata signal:任何 caller 构造 PlannedOpDTO 都能设 meta,bypass condition 是 data-level
- path-binding:bypass 是 function-level — 只有调到 specific private function 的 code path 才 bypass,private function 只能从 specific public planner 调用
- attack surface 从 "任何 DTO 构造" 收窄到 "导入 application-internal private symbol",后者是 Python 命名约定 + module boundary 保护 + grep audit 可 verify
- 跟 Slice 2 SF2 三层 enforcement model 的 "intentionally unguarded" 边界一致 — entity-delete 整批 revoke 是 ADR-IC §4.1 锁定路径,通过 structural unique path 实施

Audit row 显式记录 P1 amend 推翻 rationale + 修复 lock 设计 防未来 reviewer 误读 draft 残留 metadata marker wording。
