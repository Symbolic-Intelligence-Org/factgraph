## 1. Problem

Q-NAMING decision §4.6 locks Rule / Inference DSL surface rename for v0.2.0 alpha. Audit §6 (Batch E) at `10de33b9` measured the blast radius: **Red risk, 358 hits / 115 files** (41 src, 18 test, 55 docs/workflow plus 1-tier indirect). Audit §6 hidden dependencies surfaced:

1. **Rule and Inference share DSL naming surfaces** but have **different compatibility needs**: per Q-NAMING §4.6, `Branch`→`Case` rename (as symbol/export only — see §5.3) and `target`+`head_vars`→`emits` rename apply to **legacy Inference class only**; `where`→`when` rename targets the **public application `Rule` surface** (`factgraph.sdk.Rule` = `application.protocol.Rule`) and **legacy `Inference`**, with the **legacy SDK DSL `sdk.dsl.rule.Rule.where`** treatment locked at Step 4.3 preflight 2.k (Option A migrate / B carve out / C active-test-only) per Step 4.2 P2-1 finding. Implementation must avoid accidentally renaming application Rule internals or sweeping unrelated `where`-keyword surfaces (Query, aggregate helpers, assertion filter methods — see §5.4 carve-outs).
2. **Test/example teach-syntax cohort**: per audit §6, if `where` changes on both Rule and Inference, examples and tests that teach query syntax will all need to move in the same slice (180 test files with `where=[...]` patterns).
3. **`target` is a noisy term in the repo** (audit §6): implementation must scope rename to Inference DSL field only, NOT to all `target=`-style variable assignments across the codebase.

Per Sub-Q2 hard-cut decision (Q-NAMING §4.8.1): `.where(...)` → `.when(...)` is **hard-cut at v0.2** with no alias support. Examples / tests / docs teaching query syntax all migrate in this single slice. This matches the alpha hard-cut posture established by Q-NAMING-AD (`.save`/`.load` rename) and Q-NAMING-C (20 flat shell delete).

The Q-NAMING-AD precedent (PF-R1 Option (a) private-helper rewire) and Q-NAMING-C precedent (per-shell C-bucket classification + Sub-Q3 single-slice combined refactor + delete) inform this slice's approach: classify each rename target, identify both **shipped reality** (what's renamed) and **carve-outs** (what stays), and surface all hidden-dependency blockers at Step 4.3 preflight before scope-freeze.

### §5.2 Emit DTO shape (G5 + G6 — LOCKED Step 4.3 PF-r1: Option A)

**Locked at Step 4.3 PF-r1**: single combined `EmitSpec` dataclass.

```python
@dataclass(frozen=True)
class EmitSpec:
    target: str
    vars: list[Any]
```

`Inference.emits: EmitSpec | None = None` replaces both `target: str | None = None` and `head_vars: list[Any] | None = None`. Two old fields collapse into one new field.

**Locked rationale** (preflight PF-r1):
- Clearest hard-cut semantics (no field-rename + field-restructure mix)
- Easiest test migration pattern (single field swap in `Inference(...)` constructors)
- Parallel to existing optional field pattern in Inference shipped
- `to_authoring_payload` lowering at [`sdk/dsl/rule.py:176-177`](../../../src/factgraph/sdk/dsl/rule.py) cleanly maps `EmitSpec` to `payload["emits"]` dict (replacing existing `payload["target"]` + `payload["head_vars"]` keys)

**Options B and C REJECTED** at PF-r1 lock:
- Option B (nested attributes `Inference.emits.target` + `Inference.emits.vars` via nested dataclass) introduces unnecessary nesting complexity vs single combined dataclass
- Option C (structural alternative — drop both and replace with single `emits` field of original combined type) loses field-level granularity needed by `to_authoring_payload` lowering

Implementation provides:
1. New `EmitSpec` dataclass definition (likely in `sdk/dsl/rule.py` adjacent to Inference)
2. `Inference.emits: EmitSpec | None = None` field replacing `target` + `head_vars`
3. `__post_init__` validation for EmitSpec (target non-empty string + vars non-empty list)
4. `to_authoring_payload` updates: remove old `payload["target"]` + `payload["head_vars"]` blocks; add `payload["emits"]` block
