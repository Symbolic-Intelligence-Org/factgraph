## 1. Problem

Q-NAMING decision §4.3.1 and §4.3.2 (with Step 4.2 P2-1/P2-2 corrections from Q-NAMING decision adoption) lock 12 top-level class renames for v0.2.0 alpha. Per Q-NAMING §4.9, this is **Phase 4 (Q-NAMING-B1)**: **Yellow risk**, safe class renames that do NOT alter wire field names. Feasibility audit §3 (Batch B) at `10de33b9` measured the aggregate Batch B blast radius as 3726 hits / 331 files (Red overall), but the **class-only subset** carved into B1 phases out the largest hit counts (`SupportArtifact` 949 hits, `EvaluationOverlay` 522 hits per audit §3) while leaving field-level wire renames (`branch_index → case_index`, `atom_index → condition_index`, `engine_payload → proof`, `b{branch}.a{atom}` diagnostic keys) for Q-NAMING-B2 (Phase 5, Red, stop-gated).

**Class-level scope vs field-level scope** (critical Q-NAMING-B1 boundary):
- Q-NAMING-B1 renames **only the class symbols** (top-level type names + their TypeAliases) and **all imports/exports/type-hints/isinstance checks** that reference those symbols.
- Q-NAMING-B1 does NOT rename instance fields like `atom_index`, `atom_key`, `branch_index`, `engine_payload`, `b{branch}.a{atom}` diagnostic key strings, materialized dict keys, or any serialized wire payload field name. Those are Q-NAMING-B2 cascade scope (deferred per §4.9 stop gate).

Per Q-NAMING §4.8.1 hard-cut: no aliases, no dual-emit, old class names removed in same commit as new names introduced. Per N7 layer authority: lower-level core / authoring / adapter internal symbol names preserved where they don't appear on the renamed public class surface.

The Q-NAMING-AD + Q-NAMING-C + Q-NAMING-E precedents (PF-R1 Q-PR1 detection + Sub-Q3 single-slice + per-class classification + AD/C/E inherited preservation) inform this slice's discipline: classify each rename target, verify shipped reality at Step 4.3 preflight per Rule 1, surface any Q-PR1 sacred constraint blockers before scope-freeze.

**[LOCKED Step 4.4 PF-r1]** Sub-Q3 single-feat-commit cadence is locked for Q-NAMING-B1 per Step 4.3 preflight at `e37ef437`. Lock rationale: 114 deduped file footprint (53 src + 41 tests + 20 docs, refined from Step 4.1 hits-only estimate) + 12 mechanical class symbol renames + 0 Q-PR1 sacred blockers (PF-v1) + clean B1/B2 lower-snake helper boundary (PF-v3) + 0 shipped naming conflicts (PF-v2) collectively support single-slice landing. ### §5.2 Class-vs-field boundary (critical B1/B2 split)

**Q-NAMING-B1 IS class-rename only**:
- Class symbol definition (`class OldName:` → `class NewName:`)
- All `from X import OldName` → `from X import NewName`
- All `isinstance(x, OldName)` → `isinstance(x, NewName)`
- All type hints `: OldName` → `: NewName`
- All TypeAlias bindings `OldNameKind: TypeAlias = ...` → `NewNameKind: TypeAlias = ...`
- `__all__` exports list entries
- Docstring + comment references to class names
- Test fixture class instantiations

**Q-NAMING-B1 IS NOT field-rename**:
- Instance field names like `atom_index`, `atom_key`, `branch_index` (deferred to B2)
- Wire-serialized field names like `engine_payload` (deferred to B2 / Q-NAMING-F digest scope)
- Diagnostic key strings like `b{branch}.a{atom}` (deferred to B2)
- Materialized dict keys (deferred to B2)
- Method names within classes (no method renames in B1)
- Internal local variable names within method bodies that happen to use atom/branch concepts

**Q-NAMING-B1 IS NOT helper/function/lower-snake rename** (added Step 4.2 P2-2):

The shipped code has class-coupled lower-snake surfaces that are easy to over-rename when greping the class names. These are explicitly PRESERVED in B1 (deferred to B2 or later decision):

- **`SupportArtifact` family** (per G1 helper policy): `support_artifact_to_dict`, `support_artifact_from_dict`, `support_artifact_bytes`, `compute_support_digest`, `_row_support_artifacts`, `support_artifact` as instance variable / field / parameter name
- **`RuleLiteralPath` family**: `literal_path` as instance field / parameter / dict key
- **`RuleAddedAtom` family**: `added_atom` as instance field / parameter / dict key
- **`ProofFrameAtomVerdict` family**: `atom_verdicts` as instance field / parameter / dict key
- Any other lowercase snake_case derivative that happens to share a substring with a renamed class symbol

**Implementation discipline** (per CADENCE Rule 2 + N4 boundary):
- Class symbol rename updates only: `class OldName:` definition + imports + `__all__` + type annotations + `isinstance(x, OldName)` checks + class-name string in error messages (per §5.2.1 below)
- Lower-snake helper / function / field / parameter / dict key names are PRESERVED unchanged
- If a function takes a renamed class as parameter, only the type annotation updates (e.g., `def support_artifact_to_dict(artifact: ProofReceipt)` — function name preserved, parameter type annotation updated)

Step 4.3 preflight 2.d explicitly verifies each rename target is class-level only; field-level + wire-level + helper-function-level shifts are out of scope.

**§5.2.1 Error message policy (added Step 4.2 P3-1)**:

Several protocol / runtime checks include old class names in error message text. For hard-cut class renames per G13, the policy is:

- **Class name in error message text → UPDATE** to new class name (e.g., `"expected SupportArtifact"` → `"expected ProofReceipt"`; `"RuleLiteralPath validation failed"` → `"ConditionPath validation failed"`)
- **Field path / instance field / dict key in error message text → PRESERVE** unchanged (e.g., `"literal_path must be ..."` stays as-is; `"added_atom requires ..."` stays as-is; `"$.support_artifact[0].atom_index"` stays as-is — both `support_artifact` and `atom_index` preserved per §5.2 field-level deferral)
- **Mixed text** (containing both class name and field path) → update only the class-name token

Preflight 2.d additionally enumerates known error-message sites for spot-check.
