## Decision Notes

### 2026-05-23 — Initial scope lock

- This slice treats parent essay C98 as a broader design target, not as fully implementable shipped scope in one S-class slice.
- Shipped source reads show SDK/core/Souffle/Python already support a five-tag arithmetic substrate: `add`, `sub`, `neg`, `addc`, and `mulc`.
- Shipped source reads also show full C98 examples are not yet supportable:
  - `AttrRef` has no arithmetic operator methods.
  - SDK lowering has no `/` operator or `div` builtin.
  - core/Souffle/Python arithmetic tag sets exclude `div`.
  - numeric literals are currently `int` only.
- Therefore T2.2 is scoped as "ArithExpr substrate and ProbLog builtin parity", not full C98 completion.

### 2026-05-23 — G1-G7 visible gate mapping

- G1: Blueprint §1 and §2 cite parent essay §8.7 / §10.6.2 C98 and track plan §1.2 G1-G7.
- G2: Blueprint §4 records shipped source reads across SDK DSL, application bridge, core AST/validator/eval, Souffle, and ProbLog.
- G3: Blueprint §4 uses file:line citations for every shipped surface claim.
- G4: Blueprint §2 prefixes every goal with C98 / §8.7 or G5.
- G5: Blueprint §3 explicitly records deviations/deferred full-C98 work.
- G6: Reviewer should independently spot-check at least `BinaryExpr`, `_lower_binary_expr`, Souffle arithmetic dispatch, and ProbLog `_compile_atom`.
- G7: Blueprint §5.4 defines pre-impl precondition checks that must run before code changes.

### 2026-05-23 — Reviewer attention points

- If reviewer decides C98 cannot be split into substrate/parity and full completion, this slice should upgrade from S to M and add a decision doc before scoped anchor.
- If reviewer accepts the split, implementation must not expand into AttrRef arithmetic, `/`, `div`, or float literal support.
- If the G7 precondition finds `div` or AttrRef arithmetic already shipped after this draft, amend the blueprint before implementation.
