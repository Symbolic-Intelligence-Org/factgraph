## Decision Notes

### 2026-05-31 — Initial scope freeze rationale

- **Yellow-risk scope per Q-NAMING §4.9 Phase 4**: Top-level class renames that do NOT alter wire field names. Class symbols + their TypeAliases only; instance fields + wire-serialized field names + diagnostic key strings deferred to Q-NAMING-B2 (Phase 5, Red, stop-gated after B1).
- **12 renames per §4.3.1 (4) + §4.3.2 (8 including P2-1/P2-2 corrections)**:
  - G1-G4 (§4.3.1): SupportArtifact → ProofReceipt; EvaluationOverlay → FactOverlay; FactValueOverride → ReplaceFact; FactRemoveAction → RemoveFact
  - G5-G8 (§4.3.2 descriptor/locator/verdict): AtomDescriptor → ConditionDescriptor; DiagnoseAtomLocator → DiagnoseConditionLocator; WhyNotAtomLocator → WhyNotConditionLocator; ProofFrameAtomVerdict → ProofFrameConditionVerdict
  - G9-G10 (§4.3.2 + P2-1 corrections drop Rule prefix): RuleAddedAtom → **AddedCondition** (not RuleAddedCondition); RuleAddedAtomKind TypeAlias → **AddedConditionKind**
  - G11-G12 (§4.3.2 + P2-2 corrections drop Rule prefix): RuleLiteralPath → **ConditionPath** (not RuleConditionPath); RuleLiteralPathKind TypeAlias → **ConditionPathKind**
- **B1/B2 class-vs-field boundary** (§5.2 critical): class symbol rename only. Instance fields like `atom_index`, `atom_key`, `branch_index`, `engine_payload`, `b{branch}.a{atom}` diagnostic keys all deferred to Q-NAMING-B2. The "atom" prefix in *class names* is what Q-NAMING-B1 renames; the "atom" in *field names* / *key strings* is Q-NAMING-B2 scope.
- **No naming conflicts verified at Step 4.1 scan**: all 12 new names return 0 shipped occurrences in `src/`. No shadowing risk.
- **Initial Q-PR1 boundary observation**: 11 of 12 classes live in `application/protocol/` (not Q-PR1 sacred). `SupportArtifact` lives at `core/store/_support.py:97` — `_support.py` is NOT in Q-PR1 sacred list per §4.8.6. Preflight 2.a explicitly verifies this; no PF-R1-style blocker expected.
- **8-class concentration in derivation_fact_overlay.py**: FactValueOverride, FactRemoveAction, EvaluationOverlay, RuleAddedAtom, RuleAddedAtomKind, RuleLiteralPath, RuleLiteralPathKind plus their internal cross-references all in single file. Preflight 2.e verifies cross-rename ordering consistency.
- **Q-NAMING-E precedent reuse**: PF-R1 Q-PR1 detection discipline (verify each class symbol against sacred paths before lock), single-slice cadence per Sub-Q3, AD/C/E inherited preservation (N12/N13/N14 explicit).
- **Hard-cut per §4.8.1**: no aliases, no dual-emit, old class names removed in same commit as new names introduced. Alpha release; no historical user protection burden.
- **Sub-Q3 single-slice cadence**: all 12 class renames likely land in one feat commit unless Step 4.3 preflight surfaces blocker.
