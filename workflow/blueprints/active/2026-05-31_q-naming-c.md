## 1. Problem

Q-NAMING decision §4.4 locks deletion of 20 legacy SDK flat shell methods on `SDKStore` (and the `FactGraph = SDKStore` alias) — i.e., the `fg.<method>(...)` top-level call surface that predates the namespaced-manager redesign. Audit §4 (Batch C) at `10de33b9` measured the blast radius: 132 hits / 33 files (4 src, 2 test, 27 docs/workflow) — Yellow risk, low external callsite blast. **Hidden dependency** flagged by audit §4: five namespaced managers (`_SDKEvalManager`, `_SDKWhatIfFactOverlayManager`, `_SDKWhatIfRuleManager`, `_SDKWhatIfManager`, `_SDKAuditManager`) currently delegate to the very flat shells we are deleting via `self._sdk.<method>(...)`. A naïve delete would break the namespaced managers.

Sub-Q3 (locked at Q-NAMING adopt) requires **single-slice combined refactor + delete**: move flat-shell bodies into namespaced manager method bodies or private helpers, then delete public flat shells, all within one blueprint. This matches the Slice 3a Step 7 precedent and the Q-NAMING-AD §5.4.1 Option (a) precedent (private helper in `_SDKAuditManager` reaching core through `self._sdk._store.<method>(...)`).

Q-NAMING-AD already partially completed this work for `_SDKAuditManager.explain` and `_SDKAuditManager.conflicts` (rewired to call `self._sdk._store.explain_fact/.conflicts` directly per AD PF-R1 Option (a)). Q-NAMING-C completes the same pattern across the remaining four namespaced managers + handles the final flat shell deletion + decides the `commit_assertions` fate (Q-NAMING §4.4.2 explicit TBD).

## 2. Goals

- G2: Rewire `_SDKWhatIfFactOverlayManager` (2 methods: `check` delegating `check_fact_overlay`; `recheck_proof_frame`) — same pattern.

- G5: Rewire `_SDKAuditManager.diff_proof_frames` (the remaining audit-namespace delegation post-AD). Q-NAMING-AD already rewired `explain` + `conflicts`; G5 closes the audit manager rewire.
- G6: Delete 20 flat shell methods from `SDKStore` (audit §4 list): `check`, `diagnose`, `why_not`, `evaluate`, `run`, `accept`, `accept_many`, `explain`, `explain_fact`, `conflicts`, `check_fact_overlay`, `recheck_proof_frame`, `check_rule_disable`, `check_rule_literal_replace`, `check_rule_add_condition`, `diff_proof_frames`, `inspect_rule`, `inspect_semantics`, `validate_provenance`, `ingest`.   - **G7b (migrate)**: move to namespaced manager (likely `fg.assertions.commit` or `fg.batch.commit`); flat removed.
  - **G7c (delete)**: extract private helper + remove flat shell; internal source callers migrated to private helper.
- G8: Hard-cut per §4.8.1 — no aliases, no dual-emit, old names removed in same commit as rewires land.

### §5.3 `commit_assertions` decision (G7)

Q-NAMING §4.4.2 explicit TBD. Decision locked at Step 4.6 scoped anchor (latest) or Step 4.3 preflight (preferred). Three options:

- **G7a (keep)**: `commit_assertions` retained as documented `SDKStore.commit_assertions` method; not in delete list; current 37 callsite hits preserved. Q-NAMING-C scope reduced by one shell. Decision rationale: real source usage indicates this is not a legacy shell but a named ergonomic API.
- **G7b (migrate to namespaced manager)**: `commit_assertions` body moves into a namespaced manager method (e.g., `fg.assertions.commit(...)` or `fg.batch.commit(...)`); flat `SDKStore.commit_assertions` removed; 37 callsites migrated to namespaced form. Larger blast but matches deletion pattern of the other 19 shells.
- **G7c (delete + private helper)**: same as G6 pattern for shells with internal callers — extract private helper `_commit_assertions_internal(...)`, migrate 6 source callers (per audit §4) to private helper, delete public flat shell. 3 test callers + 3 doc callers migrate to whichever public path remains.

Step 4.3 preflight rationale + spot-check determines the choice. Default if ambiguous: G7a (keep) — preserves real usage with no churn.

### §5.4 Internal source caller migration

For each flat shell with internal source callers (audit §4 listed `commit_assertions` as 6 src + `run` / `evaluate` / others may have similar), the implementation **must** migrate internal source callers before deleting the flat shell. Pattern:

1. Identify each internal source caller of the to-be-deleted flat shell (Step 4.6.5 pre-impl grep produces the exhaustive list).
2. For each caller, route through the private helper / namespaced manager body the rewire (G1-G5) introduces.
3. Verify the namespaced manager path produces operationally equivalent output to the old flat shell (per AD precedent: same arguments, same return shape).
4. Delete the flat shell only after all internal callers are migrated.

### §5.7 Q-NAMING-AD precedent reuse pattern

When implementing G1-G5 rewires, the implementation MAY:
- Reuse the AD precedent for `_SDKAuditManager.explain/.conflicts` as a structural template: private helpers in the manager body reaching `self._sdk._store.<core_method>(...)` directly OR via free functions when no core public method exists.
- Where a flat shell's body is non-trivial (more than a thin wrapper over a core/application call), extract a private module-level function under `sdk/_internal/` (or similar location pinpointed at preflight) and call it from both the namespaced manager and any internal source callers.
