# Ledger SQLite 持久化实现记录

- 范围：`src/factpy_kernel/core/store/ledger.py`、`src/factpy_kernel/core/evidence/write_protocol.py`
- 状态：已实现
- 验证：`499 tests`，其中 `25 errors` 为缺失文档文件，与本次实现无关

## 目标

- 让 Ledger 中的事实数据可以在进程重启后恢复
- 保持 `:memory:` 模式可用，替代旧纯内存实现
- 不改变现有查询接口和上层调用方式
- 让 `write_protocol` 统一走 Ledger 的原子写入入口

## 实际落地结果

### 1. Ledger 迁移为 SQLite write-through cache

- SQLite 是持久化真相
- 内存 dict/list/set 是读缓存
- `Ledger()` 默认仍然是 `:memory:`，文件模式使用 `Ledger(path=...)`
- 初始化时通过 `_load_from_db()` 回放 SQLite 内容并重建内存索引

读写模型如下：

```text
reads  -> 内存索引
writes -> SQLite 事务提交成功后，再更新内存索引
init   -> 从 SQLite 全量 load，重建缓存
```

### 2. 新增两个原子写入入口

```python
append_assertion(...)
append_revocation(...)
```

二者负责在 Ledger 内部完成事务边界控制，调用方不再接触分步 `append_*`。

### 3. `write_protocol` 已切换到原子入口

- `set_field(...)` -> `append_assertion(...)`
- `retract_by_asrt(...)` -> `append_revocation(...)`
- `ingest_key` 幂等由 `Ledger` 内部处理

### 4. ingest_key 幂等迁移到独立表

- 新增 `ingest_keys` 表
- 快路径走 `ingest_keys`
- 历史数据兼容通过 lazy backfill 完成
- 进程内额外维护 ingest-key 值索引，避免 fallback 反复退化为线性扫描
- 同一 `ingest_key` 对应 assertion 若已被撤销，允许重新写入

### 5. 测试兼容层已补齐

- 保留 `copy.deepcopy(ledger)` 支持
- 提供 `_force_replace_meta_rows(...)` 作为测试专用后门
- 旧 `_meta_rows` 直访测试已全部迁走

### 6. 旧 `append_*` 接口仍保留，但已标注 deprecated

以下四个方法仅作为兼容期接口保留：

- `append_claim`
- `append_claim_args`
- `append_meta`
- `append_revokes`

当前唯一有意保留的调用点是 `test_write_protocol_v1.py`，用于构造 legacy 数据并验证 ingest-key lazy backfill。

## benchmark

### 原始基线

| 场景 | 3k rows | 10k rows |
|---|---:|---:|
| `compute_chosen_for_predicate` | 11.27ms | 44.14ms |
| `project_view_facts(record)` | 60.38ms | 233.19ms |
| `resolve_mapping_predicate` | 22.29ms | 81.65ms |

### 当前结果

| 场景 | 3k rows | 10k rows |
|---|---:|---:|
| `compute_chosen_for_predicate` | 12.46ms | 44.03ms |
| `project_view_facts(record)` | 74.09ms | 239.06ms |
| `resolve_mapping_predicate` | 27.61ms | 80.34ms |

结论：

- 3k 和 10k 两档都已回到原始基线量级
- 3k 小规模下仍有小幅常数项开销
- 10k 规模已基本持平

## 状态更新与剩余遗留项

### Q3. `SDKStore` 恢复工厂方法（已关闭）

已完成。`SDKStore.from_schema_classes(..., ledger_path=...)` 现已支持：

- 打开或创建 file-backed Ledger
- 首次创建时写入 `schema_digest`
- 后续恢复时校验 schema digest 一致性
- `ledger` / `ledger_path` 互斥校验

### Q4. 旧 `append_*` 最终清理

等 `test_write_protocol_v1.py` 中的 legacy backfill 测试不再依赖旧入口后，可将四个 deprecated 方法降级为私有或删除。

### Q5. 多进程支持

当前明确不做。文件型 SQLite 如果被多进程同时写入，内存缓存会陈旧；后续如有需要，需要单独设计缓存失效/刷新机制。
